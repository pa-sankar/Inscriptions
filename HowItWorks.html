Reading the original scans

The source is a scanned book, decades old, in a mix of English apparatus and vernacular (Tamil, Kannada, Telugu, Sanskrit) script, often with diacritical marks (ā, ṛ, ḻ, ñ, ...) that plain OCR software reads unreliably or drops outright. Every page was read using an AI vision model instructed to transcribe exactly what's printed, diacritics included, rather than a traditional OCR engine — the difference matters most on exactly the marks that carry real linguistic information.

Turning a page of text into structured records

Once a page is transcribed, each individual inscription record on it is identified and its own attributes pulled out separately: a survey/ serial number, the find-spot as printed, the dynasty and ruler named (if any), a date, the language and script, and the descriptive remarks. These become the columns of the searchable table — one row per inscription record, not one row per page.

Location: what's printed vs. what's resolved

A find-spot is often only stated in full the first time it's needed — the next several inscriptions from the same place just say "same taluk" or similar, trusting the reader to remember. The site follows that same reasoning: each record's Location column shows either what was directly printed on that page, or a value derived some other way — resolved by tracing back to whichever earlier record last stated a real place, matched against the volume's own contents/topographical table, or geocoded from the printed text. Hover either kind of value on the table itself to see exactly where it came from. Where it can be determined unambiguously, the modern Indian state (Tamil Nadu, Karnataka, Andhra Pradesh, ...) is shown alongside the resolved location too.

A real example (South Indian Inscriptions, Vol. IV)
No. 24 — Place/Source: (not printed on the page directly) → Location: Gengauur, Vellore, ANANTAPUR (matched against the volume's own contents table)
No. 25 — Place/Source: "SAME TALUK" → Location: Vellore, ANANTAPUR (inherited from No. 24 — taluk and district only, since "same taluk" doesn't claim the same village)

"Ibid."-style cross-references in the Remarks column (pointing back at an earlier citation, e.g. "Ibid., Vol. VIII, pp. 138 ff.") have been resolved to their full citation the same way, for every record where the underlying citation is another record in this corpus. (Some records cite an entirely different publication instead — e.g. "A.R.Ep., 1914" or "Ind. Ant., Vol. XIX" — there's nothing on this site for those to resolve to.) Where resolved, the underlined word in Remarks carries the full citation as a hover tooltip.

Annual Report on [South] Indian Epigraphy (ARE): a different kind of source

ARE is structured differently from SII — instead of narrative prose, its most useful content is printed as tables: one row per inscription, with Place, Dynasty, King, Date, Language and Remarks already broken into columns by the original editors. That shape makes a few extra processing steps necessary before the table is usable.

Reading sideways-printed tables

Several volumes print their appendix tables rotated 90° across the page — a layout choice from the original printing, not a scanning artifact. 1992-93's own appendix table runs this way for 86 consecutive pages. Reading these requires first detecting which pages are rotated, then rotating the page image itself before it's handed to the AI model for transcription — read as printed, a rotated page's column headers and text come out reversed and out of order. Volumes that aren't rotated are read exactly as scanned; this handling applies only where the source itself demands it.

"Do." and "Ditto": filling in what the table leaves to the reader

Like most ledger-style tables, ARE's printed convention is: when a value repeats from the row above, don't reprint it — just write "Do." (ditto). A reader working through the book in order has no trouble following this; a searchable table where any row can be the first one you see does. The site resolves a "Do." cell to the actual value it stands for by tracing back to the nearest row above that states it directly — including across a page break, where the run continues from the bottom of the previous page.

A real example (ARE 1959-60, Appendix B)
No. 566 — Place/Source: "Gopīsar (Bhakharwāla).—Stone at Gōpāljī kā thān about a mile from Gopīsar."
No. 567 — Place/Source: "Do. Another stone" → "Gopīsar (Bhakharwāla).—Stone at Gōpāljī kā thān about a mile from Gopīsar. Another stone."

Not every "Do." is resolved automatically. Where a cell is a partial ditto — some text repeated, but followed by a new detail whose exact split point isn't stated by the cell itself (e.g. "Do. No. 2 (Museum Acc. No. 149/64)") — the site leaves it to a human to confirm rather than guess at the boundary.

District and taluk names: printed once, understood everywhere below

A page heading like "VIDISHA DISTRICT / BASODA TAHSIL" is printed once, above a run of rows, not repeated on every row — exactly the same convention SII's own Location column already follows (see above). The site carries that heading down through every row beneath it until a new heading appears, so even a row with no location information of its own (just "Left side. Do.") still shows the correct district and taluk.

A real example
Sl. No. 134–138 all show Location "VIDISHA DISTRICT / BASODA TAHSIL" — only 134 and 135 actually name a village in their own Place/Source text; 136–138 inherit the district/taluk from the same heading above them.

"Ibid." citations: chasing a reference back to its full form

A record's Remarks sometimes cite an earlier publication only as "Ibid." — "same source as the record just discussed" — trusting a reader working through the book in sequence to already know what that is. The site resolves this by finding, earlier in that same appendix's own run, which record first stated the citation in full, and attaching that full citation to every "Ibid." that follows it, until a genuinely different citation appears.

A real example (ARE 1967-68, Appendix B)
No. 111 — Remarks end "...Ibid., p. 55, No. 97." → resolved by finding that an earlier record in the same run had already stated the source in full: "Hiralal's List, second edition, p. 55, No. 97."

As with SII, a citation to an entirely different publication this site doesn't hold (e.g. "Ep. Ind., Vol. XIX") has nothing to resolve to, and is left as printed.

Reading a long record

A record's remarks can run to many lines for a heavily-discussed inscription. Long remarks are visually clipped in the table with a "Read more" link that opens the full text in a popup — this only affects how it's displayed, the full text is always there.

Viewing the original page

Some records have a button to view the actual scanned page image alongside the transcription. This isn't available for every record — each page image adds real file size to what's published, and hosting a scan for every page of the whole corpus would grow well beyond what's practical for this site's own repository. Page images are included selectively, not for the whole corpus.
